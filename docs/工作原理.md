# 这个系统是怎么工作的

仿真里有一台装了两指夹爪的 UR5e。它站在桌子上，把桌上的小圆柱从一侧搬到另一侧。

可以把它看成一条流水线：先描述机器人长什么样，再算出手臂该怎么动，然后在 Gazebo 里真的把关节转过去，最后由一段固定脚本把“抓起来、转过去、放下”按顺序做完。

## 四个包各管一件事

| 包 | 它负责什么 |
| --- | --- |
| `Universal_Robots_ROS2_Description` | UR5e 的连杆、关节和外观。本仓库直接用官方模型。 |
| `robot_gripper` | 在 UR5e 的 `tool0` 上装一个夹爪，并写上 Gazebo 里用的关节控制接口。 |
| `moveit_robot_setup` | MoveIt 的规划配置：哪几个关节是手臂、哪几个是夹爪、怎么避碰、轨迹交给哪个控制器。 |
| `robot_move` | 仿真世界（桌子和圆柱），以及真正执行搬运的程序。 |

## 启动之后，谁在干什么

先开仿真和规划：

```bash
ros2 launch robot_move gazebo_move.launch.py
```

这个 launch 会同时拉起这些部分：

1. **Gazebo** 加载 `robot_move/worlds/empty.sdf`。世界里有地面、一张 2 m × 2 m × 0.8 m 的桌子，以及桌子上的蓝色小圆柱。
2. **时钟桥** 把仿真时间接到 ROS，后面的节点都用仿真时间。
3. **robot_state_publisher** 发布机器人模型，话题名是 `robot_description`。
4. **ros_gz_sim create** 按这个模型，把机器人放进 Gazebo，名字是 `robot_gripper`。
5. **三个控制器** 被激活：
   - `joint_state_broadcaster`：把当前关节角度发出去
   - `arm_controller`：管手臂 6 个关节
   - `gripper_controller`：管左右两根手指
6. **move_group**：MoveIt 的规划节点。它知道机器人形状、碰撞体和控制器。
7. **RViz**：用来看规划出来的轨迹。

机器人模型进 Gazebo 之后，URDF 里的 `gz_ros2_control` 插件会在仿真里接管关节。控制器发出“转到某个角度”的轨迹，Gazebo 里的关节就跟着动。

仿真起来之后，再开搬运程序：

```bash
ros2 launch robot_move run_move.launch.py
```

它只启动一个节点 `robot_move_execute`（源码在 `robot_move/src/robot_motion_source.cpp`）。这个节点不直接转关节，它只向 MoveIt 提要求。

另外还有一条不进 Gazebo 的路：`ros2 launch moveit_robot_setup demo.launch.py`。那是 MoveIt 自带的演示，关节由假硬件（`mock_components/GenericSystem`）带动，用来在 RViz 里看规划，没有桌子和圆柱。

## 一条动作是怎么走到关节上的

```text
robot_move_execute          move_group              控制器                 Gazebo
设定目标位姿或关节角  --->  求逆解、避碰、出轨迹  --->  arm / gripper   --->  关节转到目标
        ^                                              |
        |________________ 读回当前关节状态 ______________|
```

具体来说：

1. 程序用 `MoveGroupInterface` 打开两个规划组。`arm` 是从 `base_link` 到 `tool0` 的 6 轴手臂，`gripper` 是两根手指。
2. 手臂目标有两种给法。给名字 `home` 或一组关节角，MoveIt 做关节空间规划；给一个末端位姿，MoveIt 用 KDL 求逆解，再规划一条不撞到桌子的路。靠近圆柱时改用直线路径（`computeCartesianPath`），让夹爪竖直下降。
3. 规划成功后，`move_group` 把轨迹发给对应控制器。手臂走 `arm_controller`，夹爪走 `gripper_controller`。两者都是 `FollowJointTrajectory`，也就是一串“某时刻、某关节、到哪个位置”。
4. Gazebo 里的硬件接口执行这些位置命令，关节状态再广播回来，MoveIt 就知道手臂现在在哪。

夹爪是两个移动关节。数值变大，两指向中间合拢，所以程序里 `0.005` 是张开，`0.015` 是夹紧。

抓取时还有一件只发生在规划器里的事：夹紧之后，程序把圆柱登记成贴在 `tool0` 上的碰撞体；松开之后再删掉。这样后半段规划会把圆柱当成已经拿在手上，避免手臂规划出穿过它的路径。Gazebo 里那根蓝色圆柱本身不会被夹爪吸住，它是世界里单独放着的模型。

## 搬运脚本在做什么

圆柱放在 `(0.5, 0.4)`，放下的位置是它的对称点 `(-0.5, -0.4)`。手臂底座装在桌面高度 `z = 0.8`。末端姿态是夹爪朝下。

顺序是：

1. 手臂回到名为 `home` 的姿势，夹爪张开。
2. 肩关节抬到一个直立的准备姿势。
3. 移到圆柱正上方，再降到抓取高度前，最后沿直线下降到抓取点。
4. 夹爪合拢，把圆柱登记成手里的物体。
5. 抬起，绕底座转约 180°，到对面的上方。
6. 下降到放下点，张开夹爪，取消“手里拿着圆柱”。
7. 直线抬起，再回到 `home`。

手臂速度和加速度都被限制在最大值的 20%，规划最长等 15 秒。

## 读代码时从哪看

| 想看什么 | 打开 |
| --- | --- |
| 整机怎么拼起来 | `robot_gripper/urdf/robot_gripper.urdf.xacro` |
| 夹爪尺寸和开合范围 | `robot_gripper/urdf/gripper_macro.xacro` |
| 仿真用的关节接口 | `robot_gripper/urdf/gazebo_env.xacro` |
| 手臂 / 夹爪分组、home 姿势 | `moveit_robot_setup/config/robot_gripper.srdf` |
| 控制器管哪些关节 | `moveit_robot_setup/config/ros2_controllers.yaml` |
| 桌子和圆柱放在哪 | `robot_move/worlds/empty.sdf` |
| 搬运每一步的坐标 | `robot_move/src/robot_motion_source.cpp` |
